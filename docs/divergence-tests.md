# Divergence Tests — Savio vs. a vanilla LLM

> **What this is in one line:** the same money questions asked to Savio and to a
> plain Gemini model, side by side, so you can *see* what Savio adds rather than
> take it on faith.

This is the evidence artifact behind Savio's core claim. It is generated by
[`scripts/run-divergence-tests.mjs`](../scripts/run-divergence-tests.mjs); the
results section at the bottom is filled in each time the script runs.

---

## Why this artifact exists

Every reviewer of an AI product asks the same skeptical question, out loud or in
their head: **"Isn't this just ChatGPT with a finance skin?"**

It's a fair question, and a vague answer ("we have better prompts") doesn't
survive it. So instead of answering with words, this artifact answers with a
demonstration: it takes Savio's actual chat endpoint and a raw, ungrounded
Gemini model, sends both the *same* questions a user like Priya would ask, and
records what each one says. The differences aren't argued — they're shown.

That makes this the strongest single piece of evidence in the Savio case study,
because it converts a list of design decisions into something a reader can
verify with their own eyes.

---

## What it compares

| | **Savio** (`chat-respond` Edge Function) | **Vanilla** (raw Gemini) |
|---|---|---|
| Knows Priya's real numbers? | Yes — grounded in her live financial state | No — answers from general knowledge |
| Output shape | Structured (verdict signal, tradeoffs, next step) or three-part prose | One free-form blob |
| Refuses out-of-scope questions? | Yes — won't pick stocks or time the market | No — will happily give investment advice |
| Guards against made-up numbers? | Yes — hallucination guard + deterministic paths | No |
| Carries context across turns? | Yes — cumulative load across a conversation | Only what's resent each turn |

Both calls use the *same underlying model* (Gemini 2.5 Flash). That's deliberate:
it isolates the variable. Any difference you see is **product work — grounding,
structure, scope, guards — not a fancier model.**

---

## The five things Savio adds (and where each is decided)

Each row below maps a visible difference in the results to the product decision
that causes it, so the artifact stays auditable against `PM_DECISIONS.md`.

1. **Grounding in the user's real data.** Savio answers "Can I afford this?"
   against Priya's actual safe-to-spend and commitments. Vanilla has no access to
   her data, so it either refuses or invents a generic answer. *(Linear
   consistency invariant; C.11 user-rules grounding.)*
2. **A three-step structure.** Savio's prose is always *Where you stand → What it
   means → What you can do.* Vanilla returns an unstructured paragraph.
   *(C.16.)*
3. **A scope refusal.** Savio declines to pick instruments, give tax advice, or
   time the market — "I help you understand your money, not manage your
   portfolio." Vanilla has no such line and will recommend a mutual fund on
   request. *(Chat surface decision #3 — the four-family scope filter.)*
4. **A hallucination guard.** Savio verifies the numbers it states; when a
   surface couldn't be guaranteed, the call was to remove the LLM from it
   entirely. Vanilla's numbers are unverified. *(D.18, D.40, E.3.)*
5. **Cumulative context.** Across a three-turn sequence (₹5K watch → ₹8K watch →
   plus a ₹1L Apple Watch), Savio accumulates the load against Priya's real
   budget. *(C.9 verdict cards; the chat grounding thread.)*

## How to read the results

Each comparison block shows the question, Savio's answer, and vanilla's answer,
plus a short **Signals** line of cheap, factual observations the script can
detect automatically (e.g. "Savio returned a structured verdict and cited a
rule by name; vanilla stated a ₹ figure it has no source for"). The Signals line
reports only what's mechanically observable — it does not editorialize. The
interpretation is yours to write, or the reader's to draw.

---

## Honest caveats (read these — they're part of the point)

- **Vanilla gets no grounding by design.** This is not an unfair fight staged to
  make Savio win; it's the *realistic counterfactual*. A user who skips Savio and
  asks a chatbot their money questions gets exactly the ungrounded answer shown
  here. The comparison reflects the real choice a user faces.
- **A stricter ablation exists.** A deeper version would give vanilla the same
  grounding context but withhold Savio's structuring/guard/scope prompt, to
  isolate the *prompt* as the only variable. That's a worthwhile V2 of this
  artifact; v1 shows the user-facing reality.
- **One persona.** All questions run against Priya's seeded state. The artifact
  demonstrates behavior, not population-level outcomes — consistent with this
  being a portfolio demo, not a launched product.
- **Model defaults drift.** Vanilla output will vary run to run; Savio's
  guarded/deterministic surfaces are far more stable. Re-running occasionally is
  worthwhile.

## How to run it

```bash
# from the repo root, with Node 22 (.nvmrc pinned)
npm run divergence-tests
```

(Reads `.env.local` automatically via Node's `--env-file`; raw invocation is
`node --env-file=.env.local scripts/run-divergence-tests.mjs` if you'd rather
skip the npm wrapper.)

Required environment variables (all already present in your Savio setup):

| Variable | Purpose |
|---|---|
| `VITE_SUPABASE_URL` | Your project URL, to reach `chat-respond` and sign in |
| `VITE_SUPABASE_ANON_KEY` | Anon key for the auth + function calls |
| `DEMO_PRIYA_EMAIL` | Defaults to `priya@savio.demo` if unset |
| `DEMO_PRIYA_PASSWORD` | Priya's demo password (already in `.env.local`) |
| `GCP_SA_JSON` | Service-account JSON (inline) **or** a path to the JSON file — used for the vanilla Vertex call |
| `VERTEX_REGION` | e.g. `asia-south1` (defaults to `us-central1`) |
| `VERTEX_MODEL` | Defaults to `gemini-2.5-flash` |
